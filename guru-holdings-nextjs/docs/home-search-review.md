# 首屏搜索审核

首页以主搜索、共同方向、机构深入三层组织。主搜索用深色研究区和高对比输入框突出；每个增减仓方向先展示两条线索、每条先列两家机构。新进/退出以及默认六家以外的机构放入原生可展开区域，全部机构链接仍保留。

输入或选择高级筛选后展示实时结果；原有股票代码、公司名、投资人别名、持仓筛选及无结果/清空行为继续复用。首页不再等待外部实时市值查询，以本季度SEC持仓与仓位变化作为首要内容；外部市值与完整机构数据在对应研究页继续提供。

搜索框下方新增共同增持、共同减持和机构持仓三个入口，分别到对应信号视图与本页机构区。高级筛选使用可键盘操作的原生折叠控件，选择的条件在收起后仍显示数量；输入框有独立可访问标签，不自动聚焦或弹出手机键盘。四语言同步。

沿用已有search_results、search_no_results、search_result_select、research_navigation事件。快捷入口仅发送固定类别home_entry及公开目标类型，不发送查询原文、用户标识或伪造参与时长。预览与本机不初始化正式Google统计；浏览器测试使用本地捕获器验证事件，不代表已验证Google生产接收。

本批只交付审核分支、测试和预览，不合并或生产发布。没有新增依赖、费用或Google权限。

恢复错误定位：旧预览的React现场记录显示main第一次接管时游标在MAIN，异步内容到达后的同一容器重放时游标已在内部DIV，且服务端DOM仍是有效的HEADER/MAIN/FOOTER。与React问题 https://github.com/react/react/issues/37584 的HostComponent重放机制一致。最终采用带key的Fragment隔离main与Flight子节点，避免宿主节点被再次认领；无UI观察器单独保留Suspense。未修改React依赖、未隐藏恢复报错。全页Suspense候选虽然消除了恢复错误，但会令部分404/308提前变成200，因此已淘汰，最终方案必须同时通过HTTP状态与浏览器回归。

独立回归入口为scripts/ui/serve-hydration-replay.mjs，使用项目内Next捆绑React编译测试夹具，不新增生产路由。真实Flight状态模型下，旧结构20/20恢复失败并替换服务端容器；带key的Fragment结构20/20无错误并复用容器；晚到达对照5/5正常。未携带Flight状态的thenable负对照也正常，说明不能用普通Promise误判该问题。最终版本仍需完整构建、SEO状态、多语言交互和云端24次禁缓存/4倍CPU减速复测。
